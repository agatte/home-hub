## Regression evidence

`tests/test_desk_l2_source_readiness.py` intentionally tests *separation* between available data and policy qualification rather than enabling any writer. It covers a raw uncalibrated EMA, a fresh lux reading from the **wrong room**, a direct future-dated generic lux-channel reading, a raw Desktop Desk observation beyond the strict activity-policy 8-second window, and an immutable ScreenSync snapshot that cannot serve as a final write fence. All cases must **abstain** when their corresponding trusted assertion is not earned. No test claims that a future caller already supplies validated sensor identity, period-specific calibration, real screen brightness or a live owner lease.

The generic `LuxChannel.is_fresh` future-stamp behavior is an **observed lower-layer limitation**, *not* evidence that the desktop HTTP route accepts arbitrary future timestamps; that route accepts up to 2 seconds forward skew and clamps larger forward skew. Do not silently change this shared channel's behavior in #370 without independent regression analysis. Similarly, `PresenceFusion.get_source_reading` intentionally returns the last raw source reading; its freshness belongs to each policy caller.
