# Research Workflows

Choose only the workflow the request needs.

- **Broad scan:** search across the research jobs in `docs/Future_Development.md`;
  treat user examples as seeds, not boundaries.
- **Focused probe:** test one idea for feasibility, novelty, alternatives, and
  HomeHub fit.
- **Hardware opportunity:** inspect installed, spare, or plausibly unrecorded
  hardware capabilities before recommending purchases.

Before proposing a new component, inspect the relevant current code/specs and
current GitHub ownership. Prefer extending an existing owner over duplicating it.
Use fresh web evidence for changing external facts and prefer primary docs or
original papers.

Preserve HomeHub authority: software evidence cannot invent physical location,
experimental sensing starts shadow-only, and research does not grant automation
or device authority.

For broad scans, deliberately widen beyond the user's seed and return only ideas
with meaningful evidence or leverage. If unknown household hardware would
materially change a recommendation, ask only the smallest useful question.

Use one bounded worker only when parallel source gathering materially helps;
otherwise keep synthesis in the main session.
